# Задача: утилита обезличивания документов (для не-технического пользователя)

Нужно написать десктопное GUI-приложение на Python, которое заменяет слова из словаря в документах (.docx, .txt) с учётом русской морфологии (склонений). Назначение — обезличивание документов перед передачей в LLM.

## Критично важно: UX
- Пользователь — человек, не умеющий работать с командной строкой. Никакого CLI вообще.
- Приложение должно запускаться двойным кликом по .exe (собрать PyInstaller'ом в один файл) и при необходимости — из исходников одной командой `start.bat` / `start.sh`, которая сама ставит зависимости и запускает.
- GUI на customtkinter (или аналогичном современном tkinter-обёртке). Интерфейс на русском языке.
- Сценарий использования максимально простой:
  1. Кнопка «Выбрать файл» (поддержать перетаскивание файла — плюс, если просто).
  2. Кнопка «Загрузить словарь».
  3. Кнопка «Обезличить».
  4. Кнопка «Сохранить результат» — сохранить как новый .docx/.txt, оригинал не трогать.
  5. Отдельный режим «Обратная замена»: загружаешь обезличенный файл + файл маппинга → получаешь исходник обратно.
- Прогресс-бар для больших документов (поток, не блокировать UI).
- После обработки показать статистику: сколько слов заменено, сколько не найдено в словаре, список замен.

## РЕДАКТОР СЛОВАРЯ/МАППИНГА (ключевая фича, НОВОЕ)
Пользователь не должен ни при каких обстоятельствах редактировать JSON/CSV руками. Всё редактирование — только через GUI:

1. **Табличный редактор пар «оригинал → замена»** (ttk.Treeview или аналог):
   - Добавление, редактирование (двойной клик по ячейке или кнопка «Изменить»), удаление строк (одной и нескольких сразу), сортировка по любой колонке.
   - Поиск и фильтрация по словарю.
   - Валидация при вводе: предупреждать о дубликатах, пустых значениях, заменах, которые совпадают с другими оригиналами (конфликты пересечения).
2. **Импорт**: CSV (разделитель автодетект: `,` или `;`), JSON, простой .txt/Excel с одной колонкой «оригинал» (тогда замена генерируется автоматически — см. п.3). Некорректные строки при импорте не молча пропускать, а показывать списком с возможностью исправить.
3. **Автогенерация замен**: кнопка «Подобрать замены автоматически» — для строк без замены генерировать похожие по типу псевдонимы (фамилия→фамилия из встроенного списка, имя→имя, отчество→отчество; определять тип слова через pymorphy3). Замены детерминированные: одинаковый оригинал всегда даёт одинаковую замену (отсортировать перед генерацией).
4. **Сохранение**: экспорт в CSV и в JSON-маппинг (тот самый файл, который используется для обратной замены). Формат JSON внутренний — пользователь его не видит никогда.
5. **Проекты**: словарь можно сохранить/загрузить как «проект» — чтобы не собирать заново для повторных документов одной тематики.
6. **Интеграция с обработкой**: после обработки документа показать диалог «Найдены слова, которых нет в словаре» — список с галочками, где пользователь одним кликом добавляет пропущенные слова в словарь (с автогенерацией замен) и перезапускает обработку. Это закрывает главный сценарий «первая обработка документа»: загрузил → увидел пропуски → дособрал словарь через GUI → готово.

## Ядро: морфологическая замена
- Библиотека: pymorphy3 (форк pymorphy2, работает на Python 3.10–3.12).
- Алгоритм:
  1. Токенизировать текст (учесть, что слова могут быть разбиты на несколько runs внутри docx — собирать текст абзаца, заменять, потом перераспределять по runs; НЕ ломать форматирование: жирный/курсив/подчёркивание должны сохраняться).
  2. Для каждого токена получить лемму через morph.parse().
  3. Если лемма есть в словаре (сравнение регистронезависимое) — взять слово-замену, просклонять его по граммемам найденного токена (inflect по tag.grammemes), если склонение не удалось — взять замену в форме словаря.
  4. Восстановить регистр оригинала (restore_capitalization или вручную: заглавная в начале предложения, ВСЕ ПРОПИСНЫЕ, и т.д.).
- Словарь хранить нормализованный (лемматизированный) при загрузке, чтобы «Сидоров», «Сидорова», «сидоровым» матчились все.
- Детерминированный маппинг: одна фамилия всегда → одна и та же замена (зафиксировать тестом).
- Генерировать файл маппинга (JSON: замена → оригинал) рядом с результатом — нужен для обратной замены.
- Обрабатывать: дефисные слова (собирать-тянуть, Санкт-Петербург), инициалы («И.И. Иванов»), аббревиатуры. Для инициалов отдельная логика: инициал, соответствующий заглавной букве имени в словаре, заменять на инициал замены.
- Не заменять внутри нерусских слов, цифр, email, URL.

## Технические требования
- Python 3.10+ (проверить на 3.11 и 3.12), зависимости: pymorphy3, pymorphy3-dicts-ru, python-docx, customtkinter, pyinstaller.
- .docx через python-docx: параграфы, таблицы, колонтитулы (headers/footers), примечания — всё обрабатывать. Текст в текстовых полях (textboxes) — по возможности.
- .txt: автодетект кодировки (utf-8, cp1251, utf-16), сохранять исходную кодировку.
- Код структурировать: core/ (морфология + заменитель), ui/ (GUI, включая редактор словаря), tests/ (pytest: минимум 15 тестов — склонения, регистр, дефисы, runs в docx, обратная замена, импорт/экспорт словаря, автогенерация замен, детерминированность).
- requirements.txt + инструкция сборки в .exe: `pyinstaller --onefile --windowed --add-data ...`.
- README.md на русском: как собрать, как пользоваться, формат словаря.

## Приёмы из хороших проектов
- shield (github.com/enki-run/shield): обязательно round-trip — обезличить, потом по маппингу вернуть исходник. Тест: обезличить → обратно заменить → diff с оригиналом должен быть пустым.
- deidentify (github.com/aliengiraffe/deidentify): детерминированность — одинаковые входы дают одинаковые выходы.
- pasteguard (github.com/sgasser/pasteguard): дашборд/лог того, что было заменено; mask/restore как два явных режима.

## Критерии приёмки
1. Берём docx с «Иванов подписал договор. Иванову передали документы. Встречал ИВАНОВА.» + словарь `Иванов → Петров` → получаем «Петров подписал договор. Петрову передали документы. Встречал ПЕТРОВА.» с сохранённым форматированием.
2. Обратная замена возвращает исходник.
3. Полный цикл без ручного редактирования файлов: загрузил документ → увидел пропущенные слова → добавил их через таблицу (или автогенерацией) → перезапустил → сохранил результат и маппинг.
4. Пользователь без терминала: двойной клик → выбрали файл → собрали/загрузили словарь → готово.
5. Никакого интернета и внешних API — всё локально.
